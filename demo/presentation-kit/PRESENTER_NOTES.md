# Presenter notes — live demo handoff

## Before recording

1. Confirm local web app and API health, and that Ollama is running.
2. Use a fresh browser profile or known test session. Clear prior demo session only in that profile; do not modify unrelated user data.
3. Capture at 1920x1080 if possible, 30fps. Keep the cursor visible, but hide OS notifications.
4. Enable the explicit simulation test mode before showing a simulated learner. Do not display internal test instructions.
5. Record genuine Teacher and Student Agent output and include the generation delay; speeding up idle waiting during editing is allowed.
6. Capture Korean language switch in the same session and a real new Korean teacher answer.
7. Capture actual Add/Remove click sequence 0 → 1 → 2 → 1 → 0.
8. Record Living Textbook as the last software proof.

## In case of failure

- Do not pretend a timed-out model output was live. Either show the failure honestly or omit the clip.
- Never replace a missing UI clip with a styled app screenshot or fake animated UI.
- The two full-screen PNG assets (`opening.png`, `ending.png`) are for editorial opening and closing only.

## Voice direction (approved)

Balanced expressive storyteller: natural, confident, moderately energetic; emphasize "adapt", "different" and the final brand name. No exaggerated announcer shouting. Original MP3 stems are stored under `../audio/`.

## Do not claim

- Proven educational improvement or higher math scores
- A complete mathematics curriculum
- Full mathematical accuracy across arbitrary topics
- That simulated learners were actual human students
